# 百度网盘自动转存订阅（Docker）

基于 [kokojacket/baidu-autosave](https://github.com/kokojacket/baidu-autosave)，保留 AGPL-3.0 许可证。上游基线：`85203fda4bb027e926494acaeb3736b1df5a93c2`。

订阅指周期检查已添加的百度网盘分享链接，将新增文件转存到自己的网盘，使用上游的去重逻辑。不是 RSS 内容聚合或文件下载器。

## 直接拉取镜像（推荐）

镜像：`ghcr.io/dandan658/baidu-autosave-docker:latest`，支持 Linux amd64 和 arm64。公开后无需登录 GHCR。

```sh
docker pull ghcr.io/dandan658/baidu-autosave-docker:latest
docker run -d --name baidu-autosave --restart unless-stopped --init \
  -p 127.0.0.1:5000:5000 \
  -e TZ=Asia/Shanghai \
  -v baidu-autosave-config:/app/config \
  -v baidu-autosave-log:/app/log \
  ghcr.io/dandan658/baidu-autosave-docker:latest
docker logs baidu-autosave
```

以上多行命令适用于 Linux/macOS shell。PowerShell 可将 `docker run` 各行合并成一行。
默认只允许本机访问。要从局域网访问，将 `-p 127.0.0.1:5000:5000` 改成 `-p 5000:5000`。

也可克隆仓库后使用预构建版本的 Compose：

```sh
docker compose -f compose.prebuilt.yaml pull
docker compose -f compose.prebuilt.yaml up -d
docker compose -f compose.prebuilt.yaml logs --tail=100
```

升级时再次运行上述 `pull` 和 `up -d`，账号和任务保留在挂载目录中。源码构建版本与预构建版本任选其一，避免同时占用 5000 端口。

## 从源码构建启动

需要 Docker Engine / Docker Desktop 和 Docker Compose v2。

```sh
cp .env.example .env
docker compose up -d --build
docker compose logs baidu-autosave
```

PowerShell 用户将第一条命令替换为 `Copy-Item .env.example .env`。
打开 http://localhost:5000 。用户名默认 `admin`。首次启动前可在 `.env` 设置 `ADMIN_PASSWORD`；留空时随机生成，查看启动日志中的 `Initial admin password`。初始化后，环境变量不会覆盖现有账号，请在界面修改密码。

## 配置订阅

1. 登录百度网盘网页版，在浏览器开发者工具的网络请求中复制自己账号的 Cookie。
2. 在本服务的用户管理中添加百度账号，填入 Cookie 并验证。
3. 新建转存任务，填写分享链接、提取码、目标网盘目录，并选择账号。
4. 设置全局或单任务 Cron。例如 `*/30 * * * *` 为每 30 分钟；`0 10 * * *` 为每天 10 点。默认时区为上海。
5. 先手动执行一次，确认目标目录与日志，再保留定时任务运行。可继续配置文件过滤和通知。

Cookie 失效后需重新填写；分享失效、验证码、账号风控或容量不足会导致转存失败。实际转存需要用户自己的有效账号与分享链接。

## v1.5.0：后台多账号登录

在「系统设置 → 账户设置 → 后台登录账号」中新增账号、重置新增账号密码或删除新增账号。每次账号管理操作都需验证当前登录者的密码。所有登录账号拥有相同后台管理权限，共享原有任务、百度网盘用户及转存记忆；不是独立的数据空间，也不是百度网盘用户名密码登录。

升级无需迁移或重新初始化：原始 `auth.users` / `auth.password` 继续有效，任务、网盘配置及记忆沿用原挂载目录。新增账号单独保存在 `auth.login_accounts`，密码只保存哈希，接口不会返回密码或哈希。原始账号不能在列表删除或由其他账号重置密码；本人仍可使用原有修改密码功能。当前登录者不能删除自己。

新增账号能修改自己的密码，不会覆盖原始账号。改密、重置密码后，目标账号其他会话失效；删除账号会撤销其登录权限，不删除任何共享数据。系统配置保存不会覆盖账号列表。配置先写临时文件再原子替换，写入失败保留原文件；仍建议升级前备份完整的 config 目录。继续使用 latest YAML 重新部署即可。

## v1.4.1：多季订阅识别

编辑电视剧任务并开启自动重命名后，会识别「第一季」「剧名第二季 完结」「第三季」「Season 02」「S03」等目录，以及十一、二十二等中文季数。同一订阅内各季都叫 `01.mp4` 或错误标为 `S01E01.mp4` 时，按所属目录分别生成 S01E01、S02E01、S03E01。嵌套目录以距离文件最近的季目录为准，单个分享根目录里的季数也会保留。

优先级：手动子目录规则 > 最近季目录 > 文件名 SxxEyy > 默认季数。合并目录只合并位置，保留文件名中的不同季数；不合并时生成独立 Season 01 / Season 02 / Season 03 目录。`001-090` 等集数范围不会被当作季数。仅影响未处理的新文件，已保存的转存记忆不会清空，也不会重新转存已移走的旧文件。

飞牛可使用 `compose.fnos.yaml`：固定 `latest` 并设置 `pull_policy: always`，以后重新部署时检查并拉取最新镜像。它不会让已运行的容器自动升级；可执行 `docker compose -f compose.fnos.yaml up -d` 更新。继续选择原来的项目目录，使用已有 `./config` 和 `./log`。

## v1.4.0：自适应玻璃界面

登录、仪表盘、任务、用户、设置及弹窗统一采用 iOS 风格的圆角玻璃界面，跟随系统深浅色。宽屏显示完整侧栏，平板使用紧凑侧栏，手机使用底部浮动导航；任务卡片、设置表单、弹窗支持窄屏。修复任务数量标记错位，表格操作固定在右侧，其余内容可在表格内横向滚动。

页面切换、弹窗、菜单和标签切换使用短距离位移与透明度动画，支持系统的减少动态效果设置。模糊仅用于导航和浮层，不对每个任务卡片应用模糊；不支持模糊的浏览器自动使用实色背景。后台刷新任务不再触发整屏加载遮罩，全局添加入口可在各页面使用。升级保留现有配置、任务和转存记忆。

## v1.3.0：任务转存记忆与交互优化

任务列表的电脑端操作栏和手机端卡片均提供「日志」按钮。只查看最近 300 条执行记录，不会重新执行任务；运行中的任务可最小化后再次打开查看。定时执行和手动执行均记录进度。日志是当前服务运行期间的内存记录，重启后清空；转存记忆独立持久化，不受日志清空影响。

成功转存记忆保存在挂载的 `config/history` 中，归属于任务稳定 ID。文件在网盘中移动或改名后不会再次转存；修改任务名称、保存目录、分季规则或重启容器不会清除记忆。仅处理新文件及可识别的内容新版本。删除任务会清除该任务的记忆及整理记录；重新创建为全新任务，不继承其他任务的记忆。转存失败的文件不记录成功，下次继续重试。

v1.2.0 的已有整理记录会自动迁移，包括已被移动但留下成功记录的文件。更早版本没有留下来源记录、且已被移走的文件无法可靠追溯，不能自动补记。请备份整个 `config`，不要只备份 `config.json`。

新增独立“提取码”输入框；支持从带 `pwd` 参数的链接自动填入，也可手动修改。明确填写的值优先，旧客户端省略该字段时仍保留已保存的提取码。修复表单标签换行和提示文字遮挡。

最小化监控窗口立即关闭，不等待日志请求。后台采用独立请求线程，最多四条实时日志连接，保留线程处理普通 API；运行进度只更新内存，不再逐条写配置及重载调度器。日志显示最多 300 条、服务端最多保留 1000 条；任务轮询避免请求重叠，页面后台暂停轮询，任务列表只在字段变化时更新。

上述优化针对界面响应和本服务开销；百度接口耗时、限流及 NAS 网络仍会影响实际转存速度。可以用 `WEB_THREADS` 调整请求线程数，默认 16，范围 8–64。

## v1.2.0：影视整理和独立分季目录

任务名称由用户填写，粘贴或修改分享链接不会再自动覆盖名称。需要获取分享标题时，点击“从链接获取名称（手动）”。路径关联也默认关闭。

编辑或新建任务时，可选择“电视剧 / 电影 / 普通文件”。“合并子目录”和“自动重命名”是两个独立开关：

- 合并开启：递归读取分享里的各级文件，统一放到保存路径；命名为 `牧神记 - S01E105.mp4` 等。
- 合并关闭：保留子目录，并支持每个季目录单独改名及设置季数。例如源 `第一季` 对应季数 1、新目录 `Season 01`；源 `第二季` 对应季数 2、新目录 `Season 02`。文件分别使用 S01、S02 命名。
- “源子目录”相对于分享的顶层文件夹，嵌套目录可写 `合集/第二季`。新目录名留空时自动用 `Season 02`。文件名中有错误季数时，以明确填写的目录规则为准。
- `001-090`、`091-100` 等目录只代表分组，不会自动当作季数。可通过目录规则指定它们的对应季数与目标目录名。
- 自动命名整理视频和字幕，保留扩展名、字幕语言后缀；不会转存图片等附件。集数无法可靠识别时明确提示并跳过，不按画质或年份数字猜测。
- 电影使用自定义任务名；同名文件自动加稳定区分后缀，不覆盖已有内容。
- 正则仅匹配文件名，支持 `$1` 与 Python `\1` 捕获组；关闭自动命名后，可单独使用正则替换。自动命名开启时以影视命名规则为准。

旧任务升级后保留原有行为，需要进入编辑页自行开启整理选项。新建任务默认选择电视剧、合并子目录、自动命名，必须填写自定义名称。已有文件会在精确来源路径和大小匹配时移动整理；不会主动删除旧的空季目录。改动规则后建议先手动执行一次检查日志；v1.3.0 起，已记忆的历史文件不会因改动规则而重新转存。

整理记录保存在 `config/organized`，与账号配置一起备份。转存先进入任务独立暂存目录，再移到最终名称；失败时保留暂存文件以便重试，界面不会把重命名失败误报为“没有新文件”。

## 持久化和维护

配置、账号凭据、任务保存在 `data/config`，日志在 `data/log`。备份这两个目录即可，勿提交到公开仓库。会话密钥也持久保存在配置目录，重启不会主动更换。

```sh
docker compose ps
docker compose logs -f --tail=100
docker compose down
docker compose up -d --build
```

默认只绑定本机。局域网部署可将 `.env` 的 `BIND_ADDRESS` 改为 `0.0.0.0`，通过服务器 IP 访问；远程使用建议经 HTTPS 反向代理。端口可通过 `WEB_PORT` 修改。

容器健康检查同时检查 Web 服务和调度器。单实例运行，避免多个调度器重复执行同一份任务。健康状态异常请检查日志；Docker 的 restart 策略只在进程退出时生效。

# v1.6.0：TMDB 资料和统一第一季

添加或编辑任务时，在资源类型下方使用 TMDB 搜索。先展开配置，填写自己的 TMDB API Key（v3）或 API Read Access Token，并设置百度网盘默认保存位置，例如 `/001`。凭据仅保存在原 `config/config.json`，不返回浏览器；留空保存会保留原凭据。也可通过容器环境变量 `TMDB_API_TOKEN` 或 `TMDB_API_KEY` 提供凭据。

选中电影或电视剧后，任务名称使用 TMDB 中文名称，保存路径生成 `/001/影片名称`。同时保存 TMDB ID、类型和年份，编辑任务时保留关联。可手动改名和改路径；仅搜索、更新配置或打开旧任务不会改动原路径。切换资源类型后需重新选择匹配资料。特殊文件名字符替换为下划线。

电视剧新增“统一第一季”开关：默认关闭，继续按手动规则、最近季目录、文件名和兜底季数识别。开启后统一使用 S01，覆盖其他季数；保留目录时使用 `Season 01`，合并时直接放入保存目录。文件重命名需开启“自动重命名”。同名冲突仍自动区分，已经记忆的旧文件不会重新转存或移动。

TMDB 搜索在点击搜索时才请求，8 秒超时；未配置或网络异常不影响普通任务编辑。资料来源 TMDB；本产品使用 TMDB API，但未经 TMDB 认可或认证。认证方式见 [TMDB 官方说明](https://developer.themoviedb.org/docs/authentication-application)。
